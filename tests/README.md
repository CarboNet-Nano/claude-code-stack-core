# Stack test suite

Tests for the stack itself. Run before any release / breaking change.

## Tests

- `test-install.sh` — install in a clean directory; verify all tiers reach pass, and that the installed `settings.json` never references a hook script that wasn't copied at that tier (the tier-0/1 team-hook dangling-reference guard).
- `test-tier-isolation.sh` — verify each tier installs cleanly without earlier tiers being polluted.
- `test-config-merger.sh` — JSON merge logic doesn't lose user data; includes a scalar-conflict scenario (non-interactive run keeps the user value).
- `test-merger-session-hooks.sh` (v1.1) — verify nested SessionStart hooks from multiple tiers merge correctly (Tier 0's hook + Tier 2's hook both fire after merge).
- `test-merger-interactive.sh` — verify the interactive conflict prompt (approve → stack value, decline → user value kept), driven through a pty via `expect`. Skips cleanly if `expect` is unavailable.
- `test-cloud-bootstrap.sh` — verify `scripts/cloud-bootstrap.sh` never hard-fails a cloud session: no-op outside cloud, warn+exit 0 on missing token, short-circuit on the per-boot marker. Offline-only (the clone+install path is covered by `test-install.sh`).
- `test-cross-family-preflight.sh` — unit tests for `scripts/lib/cross-family-preflight.sh` (ADR-022): the verdict matrix (`READY` / `BLOCKED_NETWORK` / `BLOCKED_NOCREDS` / `PROBE_SKIPPED`), `OPENAI_API_KEY` env detection, and the `cfp_log_deviation` writer. Network reachability is stubbed — no real outbound call.
- `test-design-gate-globs.sh` — unit tests for `hooks/design-gate.sh` `approved_paths` glob normalization: bare relative globs match absolute paths, `[deviceId]` bracket segments are literal by default (`glob_char_classes` opts back in), `(dashboard)` route groups, scoped denial diagnostics + near-miss hint.
- `test-handoff-guard.sh` (issue #179) — unit tests for `hooks/handoff-guard.sh`: direct Write/Edit of `.claude/next_prompt.md` or `docs/handoffs/**` is denied for every agent (ADR-074 D16 enforced at the files, not by trusting scribe's instructions), traversal-shaped paths refused, scratch/open-threads/lookalike paths stay writable, fail-open on malformed payloads, and the hooks.json wiring itself.
- `test-secret-binder.sh` — unit tests for `scripts/lib/secret-binder.sh` (ADR-035): bind-by-name emit, idempotent re-splice, fail-hard on missing/malformed `.secrets`, no-plaintext-leak guards, and the splice hardening cases 17a–17d — static symlink refusal, the symlink TOCTOU (driven deterministically by overriding `dirname`, the first external command inside the old check-then-read window), a SIGKILL mid-splice leaving nothing in the tenant checkout, and the cross-filesystem staging fallback that keeps the install an atomic rename. CF API is mocked; the live smoke is opt-in via `RUN_LIVE_CF_SMOKE`.
- `test-workflow-roster-check.sh` — unit tests for `hooks/workflow-roster-check.sh`: warn/block/quiet/off decision table, roster-name extraction (both quote forms), Tier<2 gate, always-log invariant, backward-compat with old rows lacking `roster_agents`, and the base/team settings-template split (`settings.global.template.json` vs the tier-2-only `settings.team.template.json`) plus re-merge idempotency.
- `test-agent-model-pins.sh` (issue #21) — static regression guard: no `agents/*.md` `model:`/`escalation_model:` is a fully-qualified provider id (e.g. `anthropic/claude-opus-4-8`), which breaks every custom subagent spawn under a 1M-context parent session (the harness appends `[1m]`, producing an invalid id). Also checks every `tools:` block is a single-line PascalCase CSV, not a lowercase YAML list (the F2 dead-tool-bridge cause). Cannot reproduce the live 1M-boot spawn bug itself — see `docs/runbooks/stack-cloud-overrides.md` for the fresh-session verification procedure.
- `test-capability-registry.sh` (ADR-043) — unit tests for `scripts/lib/hook-metadata.py` and the hook-aware `scripts/gen-capability-registry.sh`, run entirely against synthetic fixture repo roots via `--repo-root` (never the real repo): the `# summary:` leading-comment-block scan (valid, off-line-2, code-only false positive, missing, >200-char truncation), structure-tolerant wiring derivation (`statusLine`-only, doubly-matchered, wired-in-two-files union, reformatted/reordered/re-nested wiring stays byte-identical, empty-string matcher omitted, unrecognized top-level container fails), tier-manifest derivation and its no-manifest/wired-nowhere failure modes, the cross-kind duplicate-`id` check, hook entries' always-false recommendable/invocable flags, `capabilities[]` sort order, glob-derived (never hardcoded) entry counts, the `--repo-root`-required/no-`$0`-fallback guarantee, `--lint` parity with the non-lint failure message, `--check` freshness/missing-registry behavior, and a golden check that skill/subagent entry shape is unchanged by hook splicing.
- `test-user-docs.sh` (ADR-045) — tests for the `user-docs-writer` roster agent, the `tools/user-docs/` runner, and the `/user-docs` + `/user-docs-refresh` skills. Genuinely executed: the runner's enforcement gates against a synthetic fixture repo (manual and `reset-required` docs-tests both refused as `NEEDS-RECAPTURE`/exit 2 **without launching a browser**, base URL outside `captureBaseUrlAllowlist` → exit 5, missing storage state → `AUTH-EXPIRED`/exit 3, missing `node_modules` → `RUNNER-UNAVAILABLE`/exit 4, the `5 > 4 > 3 > 1 > 2 > 0` severity precedence, the `--json` contract shape, and the static `docsMeta` parser); the static half of the browser-grant gate (no `tools:` line, model-pins guard still passes, frontmatter name valid, no `mcp__` prefix hardcoded under `tools/`); freshness-prompt provenance (verdict vocabulary present, no `TARGET` framing, not byte-shared with `/screenshot-diff`); and repo hygiene (registry freshness, tier-3 manifest completeness with no hard `npm` requirement, 24 agent files agreeing with ADR-003, Roles 2/3 absent). **Cannot execute** the plan's live cases — dispatching the agent for a real browser tool call, the fresh-eyes acceptance gate, authoring against a running dev server, vision-based `cosmetic`/`invalidating` classification, the live cost gate, and live foreman routing. Those print as `NOT-EXECUTED` with their missing precondition and are counted separately from PASS/FAIL, so a clean run is not mistaken for full plan coverage.
- `test-live-capability-snapshot.sh` (ADR-043) — unit tests for `hooks/live-capability-snapshot.sh`, run entirely with `HOME` pointed at synthetic fixture dirs (never the real `~/.claude`): the load-bearing secret-leakage guard (`mcpServers.*.headers`/`.env`/`.args`/`.command`/URL query strings never surface in output, checked with unique sentinel strings), URL host stripping (userinfo/path/query/fragment discarded), the MCP `disabled` opt-out filter across all four value shapes (`true`/`false`/absent/the string `"true"`) plus a recursive assert that `disabled` never appears as an output field, the plugin `enabledPlugins` opt-in filter (absent and explicit `false`) proven against fully-installed plugin fixtures, the deliberate enablement asymmetry (opt-in vs. opt-out) in one shared fixture, `version:null`/`summary:null` fallbacks (no installed-plugins record, no `plugin.json`), the D8a `installPath` containment rule via `realpath` (outside `$HOME/.claude/plugins/`, and a symlink escaping it from nominally inside), the D13 scope-containment tripwire (static: no hardcoded absolute path outside `$HOME`; runtime: an empty `HOME` fixture reads nothing from the real, populated `~/.claude` on the test machine), the always-`"scope":"user"` invariant, missing/malformed-input fail-safe behavior (exit 0, any pre-existing snapshot left untouched), the atomic-write proof (temp file staged in the destination directory via a `PATH`-shimmed `mv`, plus a mechanism-agnostic inode-change check, plus a forced mid-run failure leaving the prior file byte-identical), `--print`'s no-file-written guarantee, the `~/.claude/settings.json` byte-identical-after-every-run guarantee (ADR-018 write allowlist untouched), and `mcp_servers`/`plugins` sort order plus the `remote:true` iff `http`/`sse` transport rule.

## Running

```bash
cd tests
./test-install.sh
./test-tier-isolation.sh
./test-config-merger.sh
./test-merger-session-hooks.sh
./test-merger-interactive.sh
./test-workflow-roster-check.sh
./test-cross-family-preflight.sh
./test-capability-registry.sh
./test-live-capability-snapshot.sh
```

All tests must pass for a release tag. CI runs this whole suite in the
`unit-tests` job, alongside an `install-tiers` job that installs and
verifies every tier in sequence on one runner — see
`.github/workflows/test-install.yml`.
